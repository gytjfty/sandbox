INSTALLATION
1. Preserve your existing HTML and export important saves before replacing files.
2. Use your modular-migration branch; do not overwrite the published branch first.
3. Create the folders shown above and put each supplied file in its matching path.
4. Replace the entry page with the supplied index.html, not game-runtime.js.
5. Serve the project over HTTP(S). Opening downloaded HTML directly is not the
   supported test path. The game still loads its original pinned Three.js CDN URL.
6. Open diagnostics.html on the same deployed project. Check every result.
7. Open index.html and run the browser acceptance checklist below.
8. Publish only after the browser checks pass. No repository was changed by this
   delivery, and no GitHub Pages settings were modified.

WHAT CHANGED
- Original interface remains in index.html; CSS moved to styles/atlas.css.
- Bootstrap uses ordinary .js ES modules through src/main.js.
- Main module moved to src/game-runtime.js without splitting its shared state.
- Blob worker creation replaced with an external module worker. Its body and
  request/reply protocol remain unchanged.
- Robot kernel is an imported module, not a window-global dependency.
- Material foundation is an imported module. Existing material tests and its
  inspector are separate imported modules.
- Existing window.Atlas and window.AtlasRobotBuild diagnostics remain available.
- Save-key literals, validators, and persistence algorithms were not redesigned.
- Existing in-game F2 startup checks remain in the runtime.

MIGRATION STATUS
This delivers the first controlled milestone, not the entire five-stage plan.
Materials, geometry, accounting, and IndexedDB code remain together inside
foundation.js for now. Orbital/local-gravity code, mode controllers, rendering,
and legacy saves remain in game-runtime.js. A broad application context has not
been introduced prematurely. They need dependency-by-dependency extraction in
later milestones after this browser baseline is confirmed.
No empty placeholder modules or new gameplay features were added.

BROWSER ACCEPTANCE — REQUIRED, NOT CLAIMED PASSED
- Game boots with no module-loading errors or worker failures.
- F2 checks pass in each supported preset.
- Explorer movement, directory, frame transitions, and autopilot match baseline.
- Physical Flight preview/apply/journal/save/restore match baseline.
- Local Gravity initialization, contact, and save/restore match baseline.
- Robot world creation, movement, jump, save, reload, and return match baseline.
- Material inspector opens and all 35 contract checks pass.
- Existing saves load on the SAME ORIGIN as before. A different host/origin has
  different browser storage; an empty list there does not prove save corruption.
- IndexedDB interruption and multi-tab stale-save rejection work as intended.
- Pointer lock and WebGL work in the actual target host/sandbox.

LIMITATIONS
Node-based checks do not exercise a real module Worker, WebGL, pointer lock,
browser initialization, or IndexedDB transactions. diagnostics.html exercises
an actual browser module Worker, but its results have not been run here.
The original game still has independent mode save contracts and the original
robot clock restore behavior. This migration does not claim to unify or alter
those behaviors.
